🔒 YaadFlex Confidentiality & Access Playbook (copy/paste)

1) Ground rules (put at the top of every doc/repo)

CONFIDENTIAL – YaadFlex Global Vybz
All concepts, documents, code, designs, data, and communications are proprietary.
Share strictly on a need-to-know basis. External sharing requires written approval.

2) Who gets access (and who doesn’t)

Need-to-know only. Invite per project, not company-wide.

Roles: Owner (you) • Admin • Developer • Read-only (viewer) • Vendor/Contractor (limited).

MFA mandatory (email + authenticator app) for all admins/devs.


3) Where work lives

Code: Private repos (GitHub/GitLab/Replit Teams). Disable public forks.

Docs: Private Drive/Notion/Confluence spaces with sharing OFF by default.

Secrets: .env files never in git. Use a secrets manager (Vercel/Render/Netlify/1Password).


4) Keys & credentials

Rotate API keys every 90 days (Stripe, map/SMS, email).

Separate dev / staging / prod keys. Prod keys = admins only.

Turn on IP allow-listing or deploy-token-only access where possible.


5) Contractor/Vendor flow

1. Sign NDA + Contractor IP Assignment (templates below).


2. Create user with least privilege (no billing, no secrets).


3. Grant temporary access; auto-expire after delivery.


4. On off-boarding: remove accounts, rotate keys, revoke shares.



6) Auditing

Enable audit logs (GitHub enterprise logs / Replit Team activity / Drive activity).

Weekly review: new shares, new API keys, failed MFA, repo visibility changes.


7) Data handling

Tag any export with sensitivity: Internal, Confidential, Restricted.

No customer PII in screenshots or public bug reports.

Set retention: logs 30–90 days; backups 30 days (encrypted).
