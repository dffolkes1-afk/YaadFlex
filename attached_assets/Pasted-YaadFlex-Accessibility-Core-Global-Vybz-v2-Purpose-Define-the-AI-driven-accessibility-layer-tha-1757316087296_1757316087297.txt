YaadFlex Accessibility Core + Global Vybz (v2)

Purpose
Define the AI-driven accessibility layer that powers all delivery + taxi experiences, with first-class support for blind/low‑vision, Deaf/HOH, non‑verbal users, and anyone who prefers voice or simplified interactions. Add the Global Vybz layer for worldwide reach, culture, and expansion.


---

1) Design Principles

Voice-first, text-complete: Every action possible by voice; every prompt mirrored as on-screen text.

No dead ends: Always offer an alternate path (SMS/WhatsApp, IVR, big buttons).

Local first: Jamaican English + Standard English; add Spanish/French later.

Approve-the-voice: All synthesized voice lines must be recorded/approved by Owner before release.

Simple beats clever: Two taps max on “Simple Mode”; predictable focus order; no hidden gestures.

Low-spec friendly: Works on low-end Android and flaky data.



---

2) Target Users

Blind / low‑vision

Deaf / hard‑of‑hearing (HOH)

Non‑verbal / speech‑limited

Motor or cognitive load users

Low literacy / prefers voice



---

3) Core Capabilities

1. Book / Track / Pay / Rate / Support fully by voice.


2. Parity via SMS/WhatsApp commands and IVR (phone keypad + speech).


3. Big-Button UI with TalkBack labels, high-contrast, and large fonts.


4. Live captions for all speech; on-screen transcript toggle.


5. Haptics & Earcons (vibration + short tones for confirm/alert/error).


6. Accessibility Flags on each trip/order (e.g., “Passenger is Deaf—use chat”).


7. Policy Engine (DAC) applies rules (wait-time, tour fee, hill surcharge, airport worker exception) and speaks/prints them clearly.




---

4) Interaction Modes

Voice (STT/TTS): “YaadFlex, book mi a car from Papine go New Kingston now.”

Simple Mode UI: 3 primary tiles → Ride, Delivery, Help.

SMS/WhatsApp: TAXI HWT > NEW KGN 7:30PM, STATUS 8421, CANCEL 8421.

IVR: “Press 1 to book taxi, 2 for status, 3 to cancel. Say ‘agent’ for help.”

USSD (if carrier available): Menu flows without data.

Switch/Head-pointer: Support Android Switch Access and dwell.



---

5) User Stories (samples)

Blind: “Where’s my driver?” → Spoken ETA + vibration every 2 minutes; Safe‑word “Stop updates.”

Deaf: “Chat only” tile sets driver chat mode; arrival alerts are vibration + banner.

Non‑verbal: Quick-phrases: “Text only, please.” “Drop at gate.” “I need more time.”

Low literacy: Entire flow by voice; confirmations are short + plain language.



---

---

7) Accessibility Requirements (Day‑1)

100% TalkBack labels (no unlabeled icons).

Linear focus order; no swipe traps; logical headings.

Dynamic Type (system font scaling) & High‑contrast theme.

Caption everything the system says; transcript view.

Haptic confirms on pay/confirm/cancel; earcons for arrival/timeouts.



---

8) DAC Society Integration (Governance)

Rules as data: JSON policies for wait‑time (first 5 min free), hill‑area +10%, tour/excursion +15%, airport worker exception, full‑car load surcharge.

Transparent prompts: Voice + text disclose policy changes before charge.

Appeals: “Say ‘appeal’ or tap ‘Dispute’ to record/send a voice/text note.”



---

9) Architecture (Android‑first)

Frontends: Rider app, Driver app, Web kiosk.
Adapters: STT, TTS, Telephony (IVR/SMS/WhatsApp), Haptics/Audio cues.
Middleware: Accessibility Filter (adds captions, labels, haptics), Intent Router.
Services: Booking, Pricing, DAC Policy Engine, Maps/Geo, Payments, Notifications.
Content: Prompt Pack (owner‑approved voice lines + text variants), Quick‑Phrase Library.
Storage: Accessibility prefs (TTS speed, captions on, big fonts), minimal telemetry.


---

10) Intent Map (initial)

ride.book (origin, destination, when, accessibility_flags)

ride.status (by booking_id)

ride.cancel (reason)

ride.rate (stars, tags, accessibility experience)

delivery.create (pickup, dropoff, items, pay_method)

support.help (live agent / callback / chat)

profile.accessibility.set (Deaf/HOH, Blind, Simple Mode, voice gender)

policy.explain (fare components + surcharges)



---

11) Prompts Pack (owner‑approved)

Neutral: “Confirm pickup at {pickup} and drop at {drop}. Fare estimate {fare}. Say ‘confirm’ or ‘change.’”

JA English: “Confirm pickup {pickup}, drop {drop}. Estimate {fare}. Say ‘confirm’ or ‘change.’”

Short status: “Driver {name}, {eta} away.”

Arrival: “Driver outside. Check plate {plate}.”


> All spoken lines must have text mirrors and be versioned.




---

12) Data, Privacy, Telemetry

Minimal logs: intent type, success/fail, duration; no hot‑mic recording.

Consent for any recording; transcripts stored only if user opts in.

Delete‑my‑data one‑tap command.



---

13) Offline & Low‑Connectivity

Cache last 5 intents; allow SMS fall‑through (send pending booking via SMS).

IVR fallback number shown when data fails.

Core phrases available offline (“Status”, “Cancel”, “Help”).



---

14) QA Checklist (go/no‑go)

[ ] TalkBack audit passes on all screens.

[ ] Voice parity for Book → Track → Pay → Rate → Support.

[ ] SMS/IVR parity for Book + Status + Cancel.

[ ] Simple Mode reachable in ≤1 tap.

[ ] Driver sees accessibility banner when set.

[ ] Policy prompts spoken + printed before charge.

[ ] Haptic/earcon patterns mapped and documented.

[ ] All prompts approved & localized (JA/EN).



---

15) Rollout Plan

Day‑1: Voice booking + status, Simple Mode, captions, TalkBack labels, SMS parity.
Day‑30: IVR live, policy engine wired to fare display, quick‑phrase tiles editable.
Day‑90: USSD pilot (if carrier OK), multi‑language pack, advanced analytics (opt‑in).

17) Glossary

STT: Speech‑to‑Text.

TTS: Text‑to‑Speech.

IVR: Interactive Voice Response (phone menu).

USSD: Carrier menu over GSM (no data).

DAC: Policy/Rules engine governing fares, behavior, and exceptions.
